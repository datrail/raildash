Design notes

Why this is not the dashboard we have

The hero is attribution, not volume

Today's UI leads with session and event counts. Those always go up, so they never tell you anything is wrong.

Milestone 1's exit criterion is a captured interaction carrying a real agent_id instead of null. So the largest number on the page is the share of traffic that is actually attributed, and it turns amber while any interaction is orphaned.

A refusal without a reason is noise

Borrowed from Cloudflare Zero Trust's access log, where every decision row carries its block reason and the whole log filters by decision.

A gateway that says "denied" and nothing else cannot be debugged during a demo. Reason is a first-class column, not something behind a click.

Summary first, then drill down

The pattern common to Orca and Lansweeper's posture dashboards: one screen of summary, detail on demand, never both at once.

The five posture dimensions live in the drawer, because the table needs to answer "who is below the gate" in one glance — not explain why.

Status is never colour alone

Green, amber and red cluster together for red–green colour blindness; a validator run put the worst pair at ΔE 4.5. No amount of hex tuning fixes a traffic-light triad.

So every chip pairs its colour with a glyph and a word, and the unattributed slice of the coverage bar is hatched rather than merely amber.

Mono means machine

Every value a machine produced — agent id, host, ticket, destination, timestamp, score — is monospaced. Every sentence a person wrote is not.

It costs nothing and lets you tell data from chrome without reading either.

It says what it is standing in for

RailDash is the control plane in the offline bundle. The header says so, because someone debugging a demo needs to know whether they are looking at the real Rail Center or the stand-in.
